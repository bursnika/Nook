# Playwright: наскрізні (e2e) тести Nook

Тести керують справжнім Chrome і перевіряють застосунок так, як його бачить людина: React SPA (`/app`), класичну MVC-адмінку (`/admin`) і публічні сторінки (`/p/:slug`). Окремий API, база й браузер піднімаються самі, нічого мокати не треба (Google замінює лише перехоплений редирект, див. нижче).

Задача QA2: Playwright + звіт покриття коду. Результат останнього прогону: [docs/coverage-report.md](../../docs/coverage-report.md).

## Запуск

Потрібні Node 22, pnpm і Postgres (той самий сервер, що в `apps/api/.env`, локально `localhost:5433`: `docker compose -f infra/docker-compose.yml up -d postgres`) та встановлений Google Chrome.

```bash
pnpm install
pnpm e2e:build        # збирає API (apps/api/dist) і SPA з інструментацією покриття (apps/web/dist-e2e)
pnpm e2e              # сам запускає API на порту 3300 і проганяє всі специфікації
pnpm e2e:coverage     # e2e + звіт покриття (tests/e2e/coverage)
```

Зібрати треба знову після змін у `apps/api` або `apps/web`: тести працюють зі збіркою, а не з вихідним кодом.

Корисне:

```bash
pnpm e2e editor            # лише specs/editor.spec.ts
pnpm e2e -g "Long poll"    # за назвою тесту
pnpm e2e --headed          # з видимим браузером
pnpm exec playwright show-report tests/e2e/report
```

Змінні середовища:

| Змінна         | Призначення                                                                                  |
| -------------- | -------------------------------------------------------------------------------------------- |
| `E2E_BASE_URL` | адреса вже запущеного застосунку; тоді сервер не стартує (за замовчуванням `localhost:3300`) |
| `E2E_CHANNEL`  | канал браузера: локально `chrome`, у CI не заданий (береться chromium від Playwright)        |
| `DATABASE_URL` | сервер Postgres; береться з середовища або з `apps/api/.env`, змінюється лише назва бази     |

## Як усе влаштовано

- **Окрема база.** Дані живуть у базі `nook_e2e` на тому ж сервері, що й `DATABASE_URL` (хост, порт і пароль беруться звідти, змінюється тільки назва бази). Робоча база `nook` і `nook_test` не чіпаються; `support/start-api.mjs` відмовляється запускатись проти будь-якої іншої.
- **Старт сервера** (`webServer` у `playwright.config.ts`): `support/start-api.mjs` створює базу, якщо її немає, застосовує міграції (`prisma migrate deploy`) і запускає зібраний API. Вхід Google налаштований фальшивим `GOOGLE_CLIENT_ID`, а `JWT_SECRET` одноразовий, лише для прогону. Файли завантажень лежать у тимчасовій теці.
- **Початкові дані** (`global-setup.ts`, `support/seed.ts`): таблиці очищаються (крім `_prisma_migrations` і `FeatureFlag`, які повертаються до стандартних значень), створюються користувачі Ann (власниця), Bob (учасник) і Root (платформенний адмін із `ADMIN_EMAILS`), простір «E2E Space», другий простір «E2E Other Space» лише для Ann, зі сторінкою «Welcome», опублікована сторінка `e2e-public`, три задачі (TODO / IN_PROGRESS / DONE) і подія. Для кожної людини записується стан браузера з cookie `nook_at` (JWT, підписаний тим самим секретом) у `tests/e2e/.auth/*.json`. Входу через Google в тестах немає: вони стартують уже авторизованими.
- **Фікстури** (`support/fixtures.ts`): `ann` і `bob` (окремі браузери з власним REST-клієнтом `api`), `signIn('root')` та інші, `seed` (ідентифікатори даних). Кожен тест створює потрібне через API з унікальною назвою (`unique()`) і прибирає за собою, тому тести незалежні й не залежать від порядку.
- **Без пауз.** Очікування лише через `expect(...)` і `expect.poll(...)`, які повторюються до результату. Анімації вимкнені (`reducedMotion: 'reduce'`), service worker заблокований, часова зона UTC, мова en-GB.
- **Налаштування прогону:** один воркер; у CI одна повторна спроба (`retries`), трейс на першому повторі, скриншот при помилці, HTML-звіт у `tests/e2e/report`.

## Як збирається покриття коду

1. `pnpm e2e:build` збирає SPA з `VITE_COVERAGE=true` у `apps/web/dist-e2e`. Плагін `vite-plugin-istanbul` (лише за цієї змінної) додає в `apps/web/src` лічильники виконання рядків (`window.__coverage__`); тести й `src/test-setup.ts` не інструментуються. Звичайна збірка (`pnpm --filter @nook/web build`, Docker) без змін.
2. API віддає саме цю збірку (`WEB_DIST`), а фікстура `coverage` (автоматична, `support/coverage.ts`) після кожного тесту читає `window.__coverage__` з кожної сторінки кожного контексту; сторінка, що перезавантажується чи закривається, віддає лічильники в `pagehide`. Кожне читання пишеться в `.nyc_output/<uuid>.json` у корені репозиторію.
3. `pnpm e2e:report` запускає `nyc report` за конфігурацією `.nycrc.json` (враховується `apps/web/src/**`, виключені тести, `test-setup`, `testing.ts`, фейковий транспорт) і дає HTML-звіт, `coverage-summary.json` і підсумок у консолі в `tests/e2e/coverage`. Відкрийте `tests/e2e/coverage/index.html`.

## CI

Завдання `e2e` у `.github/workflows/ci.yml`: сервіс Postgres, `pnpm install`, `prisma generate`, `npx playwright install --with-deps chromium`, `pnpm e2e:build`, `pnpm e2e:coverage`. HTML-звіт, трейси і покриття вивантажуються як артефакти (`e2e-report`, `e2e-coverage`). Завдання `deploy` чекає на нього (`needs`).

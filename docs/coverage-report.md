# Звіт про покриття коду e2e-тестами (QA2)

Покриття вимірюється для фронтенду (`apps/web/src`) під час наскрізних Playwright-тестів: тести керують справжнім Chrome, а зібраний застосунок має вбудовані лічильники виконання рядків (Istanbul). Звіт показує, яка частина коду SPA реально виконується, коли людина користується застосунком.

## Підсумок

Останній прогін: 73 тести в 9 специфікаціях, усі зелені (два прогони поспіль).

| Показник               | Покрито | Усього | Відсоток   |
| ---------------------- | ------- | ------ | ---------- |
| Оператори (statements) | 2186    | 2729   | **80,10%** |
| Гілки (branches)       | 1082    | 1652   | **65,49%** |
| Функції (functions)    | 621     | 776    | **80,02%** |
| Рядки (lines)          | 1956    | 2339   | **83,62%** |

Повний звіт із розбивкою за файлами: `tests/e2e/coverage/index.html` (генерується, у git не потрапляє).

## Що означають числа

- **Рядки** і **оператори**: яка частка коду хоч раз виконалась. Вони близькі, бо майже кожен рядок містить один оператор.
- **Функції**: яка частка оголошених функцій і обробників подій хоч раз викликалась.
- **Гілки**: яка частка варіантів розгалужень (`if`/`else`, `? :`, `&&`, `??`, `switch`) пройшла. Це найсуворіший показник, тому він найнижчий: більшість непройдених гілок це обробка помилок мережі, відмови сервера й рідкісні стани (наприклад, інтеграція з Google, яку не можна викликати без справжнього облікового запису).
- Рахується лише код, який завантажив браузер. Модулі, які браузер жодного разу не завантажив, у звіт не потрапляють (екрани завантажуються ліниво, але тести відкривають кожен із них).
- Із розрахунку виключені тести, `src/test-setup.ts`, `src/lib/testing.ts` і фейковий транспорт (`src/sync/fakeTransport.ts`), які існують лише для модульних тестів.
- Покриття бекенду тут не вимірюється: API перевіряється окремими e2e-тестами Vitest і колекцією Postman/Newman.

## Як відтворити

Потрібні Node 22, pnpm, Postgres із `apps/api/.env` (локально порт 5433) і Google Chrome.

```bash
pnpm install
pnpm e2e:build       # API + SPA з інструментацією (apps/web/dist-e2e)
pnpm e2e:coverage    # тести, потім nyc report
```

Підсумок виводиться в консоль; HTML-звіт лежить у `tests/e2e/coverage/index.html`, а `coverage-summary.json` поруч містить ті самі числа машинно. Якщо тести вже пройшли, звіт можна перерахувати без повторного запуску: `pnpm e2e:report` (сирі дані лежать у `.nyc_output`).

Як це працює (докладніше в [tests/e2e/README.md](../tests/e2e/README.md)):

1. `vite build` із `VITE_COVERAGE=true` вмикає `vite-plugin-istanbul` для `apps/web/src`.
2. Фікстура `coverage` після кожного тесту зберігає `window.__coverage__` кожної сторінки в `.nyc_output/`.
3. `nyc report` за `.nycrc.json` об'єднує всі файли й будує звіт.

У CI це завдання `e2e` у `.github/workflows/ci.yml`; HTML-звіт покриття зберігається як артефакт `e2e-coverage`.

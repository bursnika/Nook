# C21. AI-асистент планування (SSE)

Pro-функція (флаг `ai-assistant`): чат, у якому відповідь модель стрімить по токенах, а інтерфейс показує кроки й виклики інструментів. Free-воркспейс отримує `403 FEATURE_NOT_AVAILABLE`, учасник чужого воркспейсу `404`.

## Архітектура

```
SPA (fetch + ReadableStream) ──POST──► AssistantController ──► AssistantService (цикл агента, ≤ 6 раундів)
                                          │ 503 / 400 / 429 до початку стріму        │
                                          ▼                                          ├─► AssistantModel (токен ASSISTANT_MODEL)
                                   text/event-stream                                 │      ├─ AnthropicAssistantModel  (messages.stream)
                                                                                     │      └─ FakeAssistantModel       (лише тести)
                                                                                     └─► AssistantTools ─► TasksService / EventsService / PagesService
```

- Розмова **не зберігається на сервері**: клієнт надсилає всю історію з кожним запитом.
- Цикл: `step` → раунд моделі (текст стрімиться як `text`) → якщо модель викликала інструменти, для кожного `tool_call` → виконання → `tool_result` → наступний раунд. Без викликів інструментів відповідь завершена. Після 6 раундів приходить `error`, потім `done`.
- Інструменти виконуються в процесі тими самими сервісами, що й REST-контролери (кеш, realtime-події, перевірки належності до воркспейсу).
- Модель прихована за інтерфейсом `AssistantModel`; тести підставляють `FakeAssistantModel` (`apps/api/test/fake-assistant-model.ts`) зі сценарієм по раундах, тому мережа й ключ не потрібні.
- Фронтенд: `apps/web/src/assistant/`: `parseSse` (EventSource не вміє POST, тому SSE читається з `fetch` і розбирається вручну), `turns` (стан відповіді), `RichText` (безпечний рендер без `dangerouslySetInnerHTML`), `AssistantPage`.

## Ендпоїнт

`POST /api/workspaces/:workspaceId/assistant/chat`

```json
{ "messages": [{ "role": "user", "content": "Що горить цього тижня?" }] }
```

Валідація: 1-40 повідомлень, кожне до 8000 символів, роль `user` або `assistant`, розмова починається й закінчується повідомленням користувача, зайвих полів немає (інакше `400`).

| Код | Коли                                                                 |
| --- | -------------------------------------------------------------------- |
| 200 | стрім (`text/event-stream`)                                          |
| 400 | погане тіло                                                          |
| 403 | Free-план або вимкнений флаг (`code: FEATURE_NOT_AVAILABLE`)         |
| 404 | не учасник воркспейсу                                                |
| 429 | понад 20 запитів за 10 хв на користувача (є `Retry-After`)           |
| 503 | немає `ANTHROPIC_API_KEY`; відповідь приходить **до** початку стріму |

Заголовки стріму: `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`; заголовки відправляються одразу (`flushHeaders`). Кожні 15 с іде коментар `: keep-alive`, щоб проксі не закрили тихе з'єднання. Коли клієнт відключається, `AbortSignal` зупиняє запит до моделі.

## Протокол SSE

Кожна подія: `event: <назва>` і один рядок `data: <json>`, порожній рядок наприкінці.

| Подія         | Дані                                        | Коли                                       |
| ------------- | ------------------------------------------- | ------------------------------------------ |
| `step`        | `{ n, label }`                              | перед кожним раундом моделі                |
| `text`        | `{ delta }`                                 | шматок тексту відповіді                    |
| `tool_call`   | `{ id, name, input }`                       | модель викликає інструмент                 |
| `tool_result` | `{ id, name, ok, summary }`                 | результат: короткий опис для людини        |
| `error`       | `{ message }`                               | збій моделі, ліміт кроків; текст безпечний |
| `done`        | `{ usage?: { inputTokens, outputTokens } }` | завжди остання (крім відключення клієнта)  |

Після `error` теж іде `done`. Якщо клієнт бачить кінець потоку без `done`, це обрив з'єднання.

## Інструменти

Усі працюють лише в воркспейсі запиту: у схемах немає `workspaceId`, зайві поля з вхідних даних моделі ігноруються.

| Інструмент     | Вхід                                               | Що робить                                         |
| -------------- | -------------------------------------------------- | ------------------------------------------------- |
| `list_tasks`   | `status?`, `priority?`, `dueBefore?`               | до 50 задач                                       |
| `list_events`  | `from`, `to` (діапазон ≤ 100 днів)                 | події календаря                                   |
| `search_pages` | `query`                                            | сторінки за назвою (до 10)                        |
| `get_page`     | `id`                                               | назва й текст блоків (обрізається до 6000 знаків) |
| `create_task`  | `title`, `description?`, `priority?`, `dueDate?`   | створює задачу `TODO`                             |
| `update_task`  | `id`, `status?`, `priority?`, `dueDate?`, `title?` | змінює задачу; видаляти не вміє                   |
| `create_event` | `title`, `startsAt`, `endsAt`                      | локальна подія (не в Google Calendar)             |

Помилка інструмента (невірний вхід, чужий або неіснуючий id, збій сервісу) повертається моделі як `tool_result` з `is_error`, щоб вона могла виправитись; цикл не падає. Текст помилки для моделі й користувача: лише повідомлення нашої валідації або HTTP-винятків сервісів, а неочікувані збої дають фіксований рядок «The tool failed unexpectedly» (деталі лише в логах).

## Змінні середовища

| Змінна              | Типово              | Призначення                                    |
| ------------------- | ------------------- | ---------------------------------------------- |
| `ANTHROPIC_API_KEY` | (порожньо)          | ключ API; порожньо = ендпоїнт відповідає `503` |
| `ANTHROPIC_MODEL`   | `claude-sonnet-5-5` | модель                                         |

Ліміт запитів (20 за 10 хв) задано в `assistant.module.ts`.

## Як отримати ключ

1. Зареєструйтесь у [Anthropic Console](https://console.anthropic.com/) і поповніть баланс (API оплачується окремо від підписки Claude).
2. **Settings → API keys → Create key**, скопіюйте ключ (його показують один раз).
3. Запишіть у `apps/api/.env` (локально) або в `.env` на сервері: `ANTHROPIC_API_KEY=...`, перезапустіть API. У Docker Compose змінні вже прокинуті в сервіс `api`.
4. Переведіть воркспейс на Pro (Settings або картка на сторінці Assistant) і відкрийте `/w/<id>/assistant`.

Ключ це секрет: не комітьте його, не додавайте до тестів і не виводьте в логи.

## Безпека

- **Тенантність.** `workspaceId` береться лише з URL після `WorkspaceGuard` (учасник) і `FeatureGuard` (Pro). Інструменти отримують його з контексту запиту, а не від моделі; чужі `id` задач і сторінок дають «Not found in this workspace», а `pageId`/`assigneeId` з чужого воркспейсу відхиляє сам сервіс. Є e2e-тест, де модель підсовує чужі id.
- **Prompt injection.** Результати інструментів і текст сторінок потрапляють до моделі лише як `tool_result` (ніколи в системний промпт), системний промпт прямо каже вважати їх даними. Назва воркспейсу в промпті очищується від керівних символів і лапок. Небезпечних інструментів немає: нічого не видаляється, події не йдуть у Google, а наслідки обмежені одним воркспейсом.
- **Рендер.** Відповідь на фронтенді розбирає власний `RichText`: з тексту будуються React-елементи (абзаци, списки, **жирний**, `код`), HTML і посилання не створюються.
- **Секрети.** Користувач бачить лише фіксовані речення про збої провайдера; сирі тіла відповідей Anthropic не пересилаються (в лог іде лише статус і тип помилки).
- **Ресурси.** До 6 раундів і 4096 вихідних токенів на раунд, відповіді інструментів обрізаються до 8000 символів, ліміт запитів на користувача, зупинка обчислення при відключенні клієнта. Лічильник ліміту живе в пам'яті процесу: при кількох екземплярах API кожен рахує окремо.

## Тести

- `src/assistant/*.spec.ts`: форматер SSE, ліміт, інструменти (мок-сервіси), цикл агента, адаптер Anthropic проти локального «фальшивого API».
- `test/assistant.e2e-spec.ts`: 403/503/404/400/429, сценарій `list_tasks` → `create_task` зі стрімом тексту, відновлення після помилки інструмента, спроби вийти за межі воркспейсу, відключення клієнта.
- `apps/web/src/assistant/*.test.*`: `parseSse` (межі чанків, багаторядкові `data`, коментарі), `RichText`, чат із мокнутим потоковим `fetch` (кроки, текст, стоп, помилка й повтор, Pro-gate, 503).
